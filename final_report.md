# Reproducible Heart Disease Classification with DVC and MLflow

## Project objective

This submission demonstrates how data versioning and experiment tracking support a reproducible machine learning workflow. DVC identifies the exact heart disease dataset version and defines a repeatable training stage. MLflow stores each run's model settings, evaluation metrics, dataset checksum, and trained model artifact.

## Dataset and method

The project uses the supplied workspace `heart.csv` dataset, copied into `data/heart.csv`. It contains 1,025 records, 13 numeric predictor columns, and a binary `target` column. The training script creates a stratified 80/20 train/test split with a fixed random seed and fits a class-weighted random forest. It reports accuracy, precision, recall, and F1 on the held-out test split.

## DVC and MLflow roles

The `data/heart.csv.dvc` pointer stores the dataset MD5 checksum and size; the matching object is included in the local DVC cache. Git versions the pointer and pipeline metadata while DVC carries the data content. `dvc.yaml` defines the training command and its dependencies, parameters, model output, and metrics output. MLflow records parameters, the same dataset checksum, test metrics, and the model, so a run can be tied to its input data version.

## Reproduction

After extracting the folder, initialize Git once with `git init`, then stage and commit the project metadata and source files. From the project directory, install dependencies and run:

```bash
python -m pip install -r requirements.txt
dvc repro
mlflow ui --backend-store-uri ./mlruns --port 5000
```

The first The tracked dataset and matching cache object are included in the package. `dvc repro` produces `metrics.json` and `artifacts/heart_model.joblib` and logs an MLflow run. The MLflow UI is available at `http://localhost:5000`. After a dataset change, run `dvc add data/heart.csv`, commit the updated pointer and relevant code or parameters, and rerun `dvc repro`. For a previous Git commit, use `git checkout <commit>` followed by `dvc checkout`.

## Results and interpretation

The project computes test metrics at execution time and writes them to `metrics.json`; MLflow provides the corresponding run history. Metrics are intentionally generated by the recipient's reproducible run rather than stated in advance. A run's `dataset_md5` value is the link between its experiment record and the exact input file. Results are educational and do not support clinical decisions.

## Files included

`README.md` gives installation, reproduction, UI, versioning, and prediction commands. `src/train.py` runs training and tracking. `src/predict.py` loads the saved model for a single row. `params.yaml` holds the model settings, while `dvc.yaml` defines the pipeline. `data/heart.csv.dvc` and `.dvc/cache/` provide DVC metadata and the local data object. `requirements.txt` lists the Python dependencies.
